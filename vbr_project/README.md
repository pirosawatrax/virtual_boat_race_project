# VIRTUAL BOAT RACE

過去のボートレース公式データを読み込み、仮想ポイントで舟券を購入し、実際の過去の競走結果と照合するCUIゲームです。**実際のお金は使いません。**

- 対応環境: Linux (Arch Linuxでの利用を想定)
- 必要環境: Python 3.11以上
- 追加ライブラリ: 不要 (Python標準ライブラリのみ)
- データベース: SQLite (`vbr.sqlite3`)
- 画面表示: 現在は英語メニュー・英語プロンプト

---

## 1. 起動方法

### ZIPを展開

ZIPを好きな場所に展開し、`vbr_project` ディレクトリへ移動します。たとえばダウンロードフォルダに展開した場合:

```bash
cd ~/Downloads/vbr_project
```

実際の展開先に合わせて `cd` のパスは変更してください。

### バージョン確認

```bash
python --version
```

Python 3.11以上であることを確認します。

### ゲームを起動

```bash
python -m vbr play
```

初回起動時は `vbr.sqlite3` と初期シーズンが自動作成され、所持ポイントは **100,000 pt** になります。また、データ取り込み用の `data/` フォルダも自動作成されます。

起動後、次のメニューが表示されます。

```text
1) Import data files
2) Race card
3) Place a bet
4) Reveal result & settle
5) Balance & ledger
6) Statistics
7) Bet history
8) Start a new season (reset)
0) Quit
```

メニュー番号を入力して Enter を押します。終了は `0` です。

> **最初にデータを取り込んでください。** データがない状態では `Race card` などを選んでもレース一覧は表示されません。

## 2. データファイルの準備と取り込み

このプログラムはインターネットからレース情報を自動取得しません。利用者が用意した公式データファイルを読み込みます。

https://www.boatrace.jp/owpc/pc/extra/data/download.html

現在読み込めるデータは次の3種類です。

| 種類 | 内容 | ゲーム内での用途 |
|---|---|---|
| Bファイル | 番組表・出走表 | 日付、場、レース、出走選手などを登録 |
| Kファイル | 競走成績 | 着順、展示情報、払戻などを登録。結果精算に必要 |
| fanファイル | 選手期別成績 | 選手の成績やコース別データを登録 |

ファイル名だけで種類を決めるのではなく、**ファイルの中身を調べて形式を判定**します。ファイル名は任意ですが、管理しやすい名前を付けてください。

### 方法A: 自動取り込み (推奨)

ゲームを起動すると `data/` フォルダをバックグラウンドで約1秒間隔で監視します。

1. ゲームを起動します。
2. プロジェクト内の `data/` フォルダを開きます。
3. B・K・fanファイルを `data/` にコピーします。
4. コピーが完了し、ファイルサイズと更新時刻が安定すると自動で取り込みます。
5. ターミナルに `[watch] Imported ...` と表示されたら取り込み完了です。
6. 取り込んだレースはメニューの `2) Race card` から選べます。

例:

```text
vbr_project/
├── data/
│   ├── fan2604.txt
│   ├── B261001.TXT
│   └── K261001.TXT
├── vbr/
├── tests/
├── README.md
└── vbr.sqlite3       # 初回起動後に作成
```

- コピー中のファイルを読み込まないよう、サイズと更新時刻が連続したスキャンで安定してから処理します。
- 隠しファイル (名前が `.` で始まるファイル) とサブフォルダは監視対象外です。データファイルは `data/` 直下に置いてください。
- 認識できない形式のファイルは警告が出ます。ゲーム自体は終了しません。
- 自動取り込みの成功履歴はDBの `imported_files` に保存されます。同じパス・同じサイズ・同じ更新時刻のファイルは再処理しません。ファイルを更新した場合は新しい状態として再取り込みします。
- 同じデータを別のファイル名や別のパスに置いた場合は、別ファイルとして処理されることがあります。取り込み元ファイルは整理して保管してください。
- 監視は `python -m vbr play` 中だけ動きます。ゲームを終了している間に置いたファイルも、次回起動後に検出されます。

監視するフォルダを変更する場合:

```bash
python -m vbr play --watch-dir /path/to/data
```

指定したフォルダが存在しない場合は自動作成されます。

### 方法B: メニューから手動取り込み

ゲーム内で `1) Import data files` を選び、プロンプトにファイルパスを入力します。

```text
File path(s), separated by spaces (blank to cancel)> fan2604.txt B261001.TXT K261001.TXT
```

複数ファイルを空白区切りで指定できます。パスに空白を含めないでください。

### 方法C: コマンドから手動取り込み

ゲームを起動せずに、コマンドからも取り込めます。

```bash
python -m vbr import fan2604.txt B261001.TXT K261001.TXT
```

ファイルの場所に応じてパスを変更してください。取り込み後、通常どおりゲームを起動します。

```bash
python -m vbr play
```

### どのファイルを先に入れる？

基本的には同じ開催日についてBファイルとKファイルの両方を用意してください。

- Bファイルだけ: レース一覧と出走表を表示できますが、結果精算に必要なデータが不足します。
- Kファイルだけ: 結果・払戻は登録されますが、出走表の情報が十分に表示されない場合があります。
- fanファイル: 選手期別・コース別データの補足に使います。対応する期のデータがある場合、出走表の `OwnCourse2` に反映されます。

結果を精算するには、そのレースのKファイルが必要です。結果6艇分と払戻データが揃っていない場合、精算はできません。

## 3. 基本的な遊び方

ゲームの基本サイクルは次のとおりです。

1. `Race card` でレースと出走表を確認する。
2. `Place a bet` で舟券の種類、艇番、賭けポイントを入力する。
3. `Reveal result & settle` で過去のレース結果を公開し、購入済み舟券を精算する。
4. `Balance & ledger` や `Statistics` で収支を確認する。

このゲームは過去のレースを使うリプレイ方式です。実際の開催進行やリアルタイム投票は行いません。

### 3-1. Race card: 出走表を見る

メニューで `2` を入力します。

画面の案内に従って、次の順番で番号を選びます。

1. 日付
2. 競艇場
3. レース番号

選んだレースの出走表には、主に次の情報が表示されます。

| 項目 | 意味 |
|---|---|
| `#` | 艇番 (1〜6) |
| `Name` | 選手名 |
| `Cls` | 選手級別 |
| `NatWin` | 全国勝率 |
| `LocWin` | 当地勝率 |
| `Motor2` | モーター2連対率 |
| `Boat2` | ボート2連対率 |
| `Exh` | 展示タイム |
| `OwnCourse2` | 同じコースから進入した場合の選手の2連対率 |

`OwnCourse2` は該当する選手期別データが取り込まれている場合に表示されます。括弧内の数字はそのコースの集計対象数です。データがなければ `-` になります。

天候、風向・風速、波高、締切時刻などもデータに含まれていれば表示されます。

### 3-2. Place a bet: 舟券を買う

メニューで `3` を入力し、日付・競艇場・レースを選びます。出走表が表示された後、次の入力を行います。

```text
Bet types: win place exacta quinella wide trifecta trio
Bet type> win
Boats in order, e.g. 1-3-2> 1
Stake (multiples of 100)> 100
```

上の例は「1号艇の単勝に100ポイント」です。

#### 選べる舟券

| 入力する券種 | 日本語 | 選ぶ艇数 | 順番 |
|---|---|---:|---|
| `win` | 単勝 | 1艇 | なし |
| `place` | 複勝 | 1艇 | なし |
| `exacta` | 2連単 | 2艇 | 1着・2着の順番どおり |
| `quinella` | 2連複 | 2艇 | 順不同 |
| `wide` | 拡連複 | 2艇 | 順不同 |
| `trifecta` | 3連単 | 3艇 | 1着・2着・3着の順番どおり |
| `trio` | 3連複 | 3艇 | 順不同 |

艇番は `1`〜`6` を使います。同じ艇番を重複して指定することはできません。

入力例:

```text
# 1号艇の単勝
Bet type> win
Boats in order, e.g. 1-3-2> 1

# 1号艇と3号艇の2連複 (順不同)
Bet type> quinella
Boats in order, e.g. 1-3-2> 1-3

# 1着3号艇、2着1号艇の2連単 (順番が重要)
Bet type> exacta
Boats in order, e.g. 1-3-2> 3-1

# 3連単 1着1号艇、2着3号艇、3着2号艇
Bet type> trifecta
Boats in order, e.g. 1-3-2> 1-3-2
```

`place` は現在、**1艇だけ**を指定します。たとえば `1-2` と入力するとエラーになります。

順不同の券種 (`place` を除く `quinella`, `wide`, `trio`) は、入力順に関係なく同じ組み合わせとして扱われます。順番が重要な `exacta` と `trifecta` は入力順がそのまま予想順になります。

#### 賭けポイント

- 初期ポイントは100,000 ptです。
- 1口の最低賭けポイントは100 ptです。
- 100 pt単位で入力してください (100、200、500、1,000など)。
- 所持ポイントを超える賭けはできません。
- 賭けたポイントは直ちに残高から差し引かれます。

入力が成功すると、次のように購入番号が表示されます。

```text
Bet #1 placed: win 1 x 100 pts
```

これは「購入番号1、単勝1号艇、100ポイント」を意味します。

同じレースに複数の舟券を購入することもできます。ただし、結果を公開した後は、そのシーズン中に同じレースへ追加購入できません。

### 3-3. Reveal result & settle: 結果公開と精算

メニューで `4` を入力し、レースを選択します。

そのレースの結果と払戻データが揃っていれば、着順・選手名・スタート情報・レースタイム・払戻一覧が表示され、購入済み舟券を自動精算します。

- 的中: 払戻ポイントが残高に加算されます。
- 外れ: 賭けたポイントは戻りません。
- 返還扱い: 現在の仮定ルールに該当する場合、賭けたポイントが戻ります。
- そのレースに購入済み舟券がなければ、結果だけが表示されます。

払戻金額はKファイルの「100円あたり」の金額を基準に、賭けポイントに応じて計算します。たとえば100 pt購入で払戻額が1,250なら1,250 pt、200 pt購入なら2,500 ptです。

**重要:** 結果公開は取り消せません。公開済みのレースには、そのシーズン中は賭けられません。結果を公開する前に、購入内容と対象レースを確認してください。

### 3-4. Balance & ledger: 残高と入出金履歴

メニューで `5` を入力します。

現在の残高と、直近15件のポイント変動履歴が表示されます。

履歴の主な種類:

- `deposit`: シーズン開始時の初期ポイント
- `bet`: 舟券購入による差し引き
- `payout`: 的中による払戻
- `refund`: 返還による払い戻し

### 3-5. Statistics: 成績

メニューで `6` を入力します。

賭け数、的中数、的中率、賭けポイント、払戻ポイント、回収率、損益などを確認できます。券種別・競艇場別・月別の集計も表示されます。

- 的中率 = 的中した舟券数 ÷ 精算済みの対象舟券数 × 100
- 回収率 = 払戻ポイント ÷ 賭けポイント × 100
- 損益 = 払戻ポイント − 賭けポイント

未精算の舟券と返還された舟券は、回収率の集計対象から除外されます。返還分は賭け金と払戻の両方から除外する扱いです。

### 3-6. Bet history: 購入履歴

メニューで `7` を入力します。

現在のシーズンの直近30件の舟券購入履歴が表示されます。券種、選択した艇、賭けポイント、状態、払戻ポイントを確認できます。

状態は主に `open` (未精算)、`won` (的中)、`lost` (外れ)、`refunded` (返還) です。

### 3-7. Start a new season: 新シーズン

メニューで `8` を入力します。

確認プロンプトが表示されます。

```text
Reset to a new season with 100,000 pts? (yes/no)>
```

新しいシーズンを開始する場合だけ `yes` と入力してください。新シーズンは100,000 ptから始まり、過去のシーズンの履歴はDBに残ります。`no` またはそれ以外を入力すれば新シーズンは開始しません。

## 4. データベースとバックアップ

- データベースの標準ファイル名は `vbr.sqlite3` です。
- ポイント、シーズン、購入履歴、取り込み済みファイルの記録はこのDBに保存されます。
- プロジェクトを更新・展開し直すときは、既存の `vbr.sqlite3` を新しいプロジェクトへコピーすれば、ゲームの記録を引き継げます。
- 念のため、終了後に `vbr.sqlite3` を別の場所へコピーしてバックアップしてください。

別のDBを使う場合は、グローバルオプション `--db` をサブコマンドより前に指定します。

```bash
python -m vbr --db practice.sqlite3 play
python -m vbr --db practice.sqlite3 import B261001.TXT K261001.TXT
```

## 6. 現在の制限・未確認事項

1. **自動取得機能はありません。** データファイルは利用者が別途用意してください。
2. **オッズは表示しません。** 全組み合わせのオッズデータを取り込む機能はありません。
3. **K/Bファイルのレイアウト:** 現在のパーサーは手元のサンプルから推測した形式を含みます。想定外の行は異常データとして報告される場合があります。
4. **返還ルールは仮定です。** `constants.py` の `REFUND_FINISH_CODES = {F, L0, L1, K0, K1}` を返還扱いとし、`S0`〜`S2` (失格) は通常の外れとして扱っています。公式ルールとの完全な照合は未完了です。
5. **レース不成立・同着・中止:** すべてのケースを検証できていません。結果6艇分と払戻データが揃わないレースは精算できません。
6. **複勝・返還の解釈:** 払戻データと返還コードの扱いは、実データ・公式ルールとの追加照合が必要です。
7. **OwnCourse2:** レース日に対応する期別データが取り込まれている場合に表示されます。5〜10月は当年後期、それ以外は対応する前期データを参照します。
8. **自動監視中のDB:** ゲーム本体と監視スレッドは同じSQLiteデータベースを別接続で使用します。通常の操作を想定していますが、DBファイルを外部から同時に変更しないでください。

### 2026-10-01サンプルでの検証記録

README更新前の開発時検証では、2026-10-01分のサンプルについて次を確認しています。

- fanデータ: 416バイト固定長レコードとして1,643件を読み込み。
- B/Kデータ: 168レース・1,008出走を読み込み。
- BとKの登録番号、モーター番号、ボート番号がサンプル内で一致。
- 単勝・2連単・2連複・3連単・3連複の払戻組み合わせが着順と一致。

これは当該サンプルに対する検証であり、すべての開催日・ファイル形式・特殊ケースでの完全性を保証するものではありません。

## 7. ディレクトリ構成

```text
vbr_project/
├── data/                 # 自動取り込み対象のデータ置き場
├── vbr/
│   ├── importers/         # B/K/fanファイルの読み込み
│   ├── watcher.py         # data/フォルダのバックグラウンド監視
│   ├── bets.py            # 投票・精算・ポイント・統計
│   ├── settle.py          # 舟券の判定ロジック
│   ├── db.py              # SQLiteのテーブル定義
│   └── cli.py             # ターミナル画面
├── tests/                 # 自動テスト
├── README.md
└── vbr.sqlite3            # 初回起動後に作成
```

公式データの再配布は避け、利用規約を確認したうえで個人利用の範囲で使用してください。
